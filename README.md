# La Pythonerie

Un espace pour apprendre à programmer **en français**, directement dans le navigateur.

👉 **[Ouvrir la Pythonerie](https://clauderouxster.github.io/Pythonerie/)**, sans rien installer.

La Pythonerie s'adresse aux enfants à partir de 7 ans, à leurs parents et à leurs enseignants. On y écrit des programmes dans un Python en français : `si`, `sinon`, `pour … dans`, `tantque`, `fonction`, `retourne`… Ce que l'on apprend ici sert ensuite directement en Python.

🤖 **Pour Claude ou une autre IA** : le fichier [POUR_CLAUDE.md](POUR_CLAUDE.md) décrit le langage, la bibliothèque et les pièges à éviter, pour écrire des programmes qui fonctionnent dans la Pythonerie. Il suffit de donner à l'IA l'adresse de ce dépôt.

## L'écran

L'écran est découpé en trois zones :

1. **Le projet**, à gauche : son nom (un clic ouvre la liste **Mes projets**), les répertoires images, sons et données, les programmes de l'élève, que l'on peut ranger dans des répertoires, et deux listes déroulantes : **Matériels**, où l'enseignant dépose le matériel de cours (voir plus bas), et **Exemples**, des programmes à essayer, chacun dans son projet. La largeur de la colonne se règle en faisant glisser sa bordure droite.
2. **L'éditeur**, au milieu : on y écrit son programme, avec la coloration des mots, l'indentation automatique et des propositions pendant la frappe ; choisir une fonction dans les propositions l'écrit avec ses arguments (`rectangle(x, y, l, h)`), et une ligne sous l'éditeur rappelle les arguments du nom sélectionné. Un **clic droit** sur le nom d'une fonction du projet (pas d'une fonction prédéfinie) mène à l'endroit où elle est écrite, même dans un autre programme ; **↩ Retour** ramène là où l'on était. Au-dessus de l'éditeur : **⧉ Copier** (le programme, ou l'onglet de données affiché, dans le presse-papiers), **⛶** (l'éditeur en plein écran, avec la même taille de caractères ; **✕** ou Échap ramène l'affichage normal, et **▶ Exécuter** en sort, pour voir le canevas), **▦ Données** (voir plus bas), **λ LispE** (le code LispE produit, avec ses numéros de ligne), **■ Arrêter** et **▶ Exécuter**.
3. **Le canevas**, à droite : une feuille de dessin où le programme peut dessiner, écrire, faire avancer une tortue, animer des formes, afficher des images, jouer des sons et réagir à la souris et au clavier. **Effacer** le vide, **Image** télécharge le dessin en PNG, et **⛶ Plein écran** l'agrandit à tout l'écran, pour un jeu par exemple : une petite barre propose alors **▤ Console** (fait venir la console sous le canevas, ou la renvoie), **■ Arrêter** (le programme) et **✕ Quitter le plein écran** ; la touche Échap ramène aussi à l'affichage normal. Sous le canevas, la **console** affiche les messages du programme, et la ligne **`>>>`** exécute tout de suite ce que l'on y tape ; elle a son bouton **⛶**, son bouton **⧉ Copier** (tout son texte dans le presse-papiers) et son bouton **Effacer**.

Sur un écran étroit (téléphone, tablette tenue en hauteur), les trois zones s'empilent : le projet en haut, que le bouton **▴** replie, puis l'éditeur, puis le canevas et sa console.

Le bouton **📖 Mode d'emploi** ouvre un guide écrit pour les enfants, avec des exemples à copier, de petits défis et un glossaire de tous les mots du langage. Le bouton **❓ Aide** en donne un résumé, avec un sommaire et des tableaux à déplier. Le logo de la Pythonerie (`docs/images/La Pythonerie.png`, décliné en `logo-64`, `logo-96`, `logo-180` et `logo-320.png`) sert d'icône et accueille l'élève quand son projet est vide.

## Le langage en bref

```python
# Les blocs se repèrent au décalage (4 espaces) ;
# la ligne qui ouvre un bloc se termine par « : »
fonction carré(x):
    retourne x * x

pour i dans intervalle(1, 6):
    si i % 2 == 0:
        affiche(i, "est pair, son carré vaut", carré(i))
    sinon:
        affiche(f"{i} est impair")

notes = [12, 15, 9]
notes.ajoute(18)
pairs = [n pour n dans notes si n % 2 == 0]

fond("bleu clair")
couleur("jaune")
disque(400, 300, 80)
texte(330, 420, "Bonjour !")
```

| Python | La Pythonerie |
|---|---|
| `if / elif / else` | `si / sinonsi / sinon` |
| `while` | `tantque` |
| `for x in l` | `pour x dans l` |
| `def` | `fonction` (ou `def`) |
| `return / break / continue / raise` | `retourne` (ou `renvoie`) `/ sortir / continuer / lever` |
| `and / or / not / in / is` | `et / ou / non / dans / est` |
| `True / False / None` | `Vrai / Faux / Rien` |
| `class / self` | `classe / soi` |
| `try / except` | `essaie / sauf` (ou `attrape`) : `sauf:` ou `sauf(e):` |
| `match / case` / `case _` | `selon (x): / cas "a": / cas 3: / défaut:` |
| `print` | `affiche` (avec retour à la ligne), `écris` (sans) |
| `input` | `demande(question, f)` (ou `input`), `demande_nombre` (une petite fenêtre), `lire(question, f)`, `lire_nombre` (la console) : `f(réponse)` reçoit la réponse |
| `", ".join(l)` | `", ".joindre(l)` |
| modifier une variable du programme dans une fonction | `x =: …` |

Quelques règles à connaître :

- Les mots du langage s'écrivent avec leur orthographe française : `épaisseur`, `carré`, `aléatoire`, `va_à`, `lève_crayon`, ainsi que les couleurs `"gris foncé"` et `"bleu clair"`.
- Les calculs donnent les mêmes résultats qu'en Python : `7 / 2` vaut `3.5`, `7 // 2` vaut `3`, `[1, 2] + [3]` vaut `[1, 2, 3]`.
- Dans une fonction, `x = …` crée une variable locale et `x =: …` modifie la variable du programme. `x += …` modifie aussi la variable du programme quand la fonction n'a pas sa propre variable `x`, ce qui simplifie les animations.
- Un élève peut appeler ses propres fonctions et variables comme il le veut, même `somme` ou `max`.
- **Après un `:`, on va toujours à la ligne** : `si x > 0: affiche(x)` sur une seule ligne est refusé. C'est voulu, pour éviter les confusions.
- Dans `sauf:` (sans variable), `retourne` quitte bien la fonction ; dans `sauf(e):`, il ne quitte que le bloc `sauf`.
- `non` appliqué à une liste agit sur chacun de ses éléments : pour savoir si une liste est vide, on écrit `longueur(l) == 0`.

## Ce que l'on peut faire

- **Écrire et demander** : `affiche`, `écris`, `demande("Ton nom ?", f)`, `demande_nombre(...)`, `lire(...)`, `lire_nombre(...)`. **Rien n'attend l'élève en bloquant la page** : une question rend la main tout de suite, le programme continue (les animations tournent, les sons jouent), et quand l'élève a répondu, la Pythonerie appelle la **fonction de rappel** `f(réponse)`. Pour l'expliquer aux élèves, le mode d'emploi prend l'image d'un parent qui conduit son enfant à une partie de football ou de hockey : soit il reste jusqu'à la fin, et sa journée est bloquée ; soit il dit « appelle-moi quand tu as fini », et il est libre de faire autre chose en attendant. Le programme fait comme le second parent. `demande` pose la question dans une petite fenêtre sur le canevas (la même en affichage normal, en plein écran et dans une application Web), `lire` dans la console, qu'il fait d'abord apparaître si elle est cachée ; Entrée répond, Échap abandonne la question (`f` n'est alors pas appelée). `demande_nombre` et `lire_nombre` donnent un nombre, et `input` est un synonyme de `demande`. Un argument de plus est rendu avec la réponse : `demande(question, f, a)` appelle `f(réponse, a)`, ce qui permet à une même fonction de servir à plusieurs questions. Plusieurs questions à la suite sont posées l'une après l'autre, dans l'ordre ; ■ Arrêter abandonne celles qui attendent. Aucune question ne relance le programme, et l'interpréteur n'est jamais détruit en cours de route : seul ▶ Exécuter en crée un neuf. `assigne(nom, valeur)` range une valeur dans la variable du programme dont on donne le nom (un texte), comme `nom =: valeur` mais avec un nom calculé : `demande("Ton nom ?", range, "nom")`, avec `fonction range(r, variable):` puis `assigne(variable, r)`. La console se commande aussi depuis le programme : `efface_console()`, `affiche_console()` (qui la fait venir sous le canevas, même en plein écran) et `cache_console()`.
- **Calculer** : `aléatoire(1, 6)`, `arrondi`, `racine`, `somme`, `maximum`, `minimum`, `intervalle`… ; `typede(x)` donne le genre d'une valeur en français (`"entier"`, `"réel"`, `"texte"`, `"liste"`, `"dictionnaire"`, `"booléen"`, `"rien"`, ou le nom de la classe d'un objet).
- **Listes et textes** : `ajoute`, `longueur`, `trie`, `inverse`, `choisis`, `majuscules`, `découpe`, `remplace`, les listes en compréhension, les dictionnaires.
- **Dessiner** sur un canevas de 800 × 600 (ou de la taille choisie avec `canevas(largeur, hauteur)` ; `largeur()` et `hauteur()` donnent la taille actuelle), dont l'origine est en haut à gauche : `point`, `ligne`, `rectangle`, `carré`, `cercle`, `disque`, `ellipse`, `triangle`, `polygone` (avec leurs versions pleines), `fond`, `couleur` (avec des noms français, et leurs nuances `"rouge foncé"`, `"bleu clair"`…), `épaisseur`, `rgb(r, g, b)`, et `texte` avec `taille_texte` et `police` (`largeur_texte(t)` donne la largeur qu'aura le texte, en points, avec la police et la taille du moment : pour centrer un titre, `texte(400 - largeur_texte(t) / 2, y, t)`) ; lire et redessiner les **pixels** avec `couleur_pixel(x, y)`, `pixels(x, y, l, h)` et `pose_pixels(x, y, l, h, valeurs)`.
- **La tortue** : `avance`, `recule`, `gauche`, `droite`, `lève_crayon`, `baisse_crayon`, `va_à`, `oriente`, `origine`, `position`, `cap`, `montre_tortue`, `cache_tortue`.
- **La 3D** : `scène = nouvelle_scène()` commence une scène, et des primitives y ajoutent des objets, chacune rendant le numéro de l'objet : `cube(scène, x, y, z, côté, couleur)`, `boîte(…, largeur, hauteur, profondeur, couleur)`, `sphère(…, rayon, couleur)`, `cylindre(…, rayon, hauteur, couleur)`, `cône(…)`, `anneau(…, rayon_intérieur, rayon_extérieur, couleur)` (couché à plat), `lumière(scène, x, y, z)`, `caméra(scène, x, y, z, vx, vy, vz)` (sa position, et le point qu'elle regarde). `groupe(scène, x, y, z)` rend un groupe : une scène dans la scène, qui se déplace et tourne avec tous ses objets (la Lune dans l'orbite de la Terre). `montre_3d(scène)` envoie la scène d'un coup : la couche 3D apparaît **sous** le canevas 2D, devenu transparent, si bien qu'un texte écrit en 2D (un score) reste au-dessus ; `efface()` efface alors la 2D en transparent, et `fond(c)` colore le fond de la scène. Ensuite, `animer` fait la logique, comme en 2D : `déplace(o, x, y, z)`, `tourne(o, ax, ay, az)` (des degrés de plus), `oriente_3d(o, ax, ay, az)`, `colore(o, c)`, `texture(o, charge_image("terre.jpg"))`, `lumineux(o)` (éclairé par lui-même, comme le Soleil), `cache_objet(o)`, `montre_objet(o)`, `regarde(x, y, z)` (la caméra vise ce point), `caméra_libre()` (la souris fait tourner la caméra, la molette zoome) et `quand_clic_objet(f)` (`f(numéro)` reçoit l'objet cliqué). La scène est dessinée par **three.js** (WebGL, sur le GPU, avec un z-buffer), copié dans `docs/vendor/three/` (licence MIT) et chargé seulement à la première scène : un programme 2D ne le télécharge pas. Une primitive appelée après `montre_3d` ajoute aussitôt son objet. Le bouton **Image**, `capture_image`, `couleur_pixel` et `pixels` voient la scène 3D sous la 2D, comme à l'écran ; la scène n'étant dessinée qu'à l'image suivante, on lit ses pixels depuis `animer` ou un clic, pas juste après `montre_3d`. Exemple complet : le projet **« Le système solaire en 3D »** des Matériels.
- **Des objets dans le canevas** : `bouton(clef, x, y, texte, f)`, `bouton_image(clef, x, y, image, [image_appuyée,] f)` (un bouton qui a la forme d'une image, éventuellement dessinée puis copiée par `capture_image(x, y, l, h)`), `case_à_cocher(clef, x, y, texte, f)`, `bouton_radio(clef, groupe, x, y, texte, f)`, `glissière(clef, x, y, mini, maxi, valeur, f)`, `liste_déroulante(clef, x, y, éléments, f)`, `liste_hiérarchique(clef, x, y, lignes, arbre, f)` et `zone_édition(clef, x, y, lignes, f)`, en plus du champ `saisie`. Chacun appelle `f` quand on s'en sert, toujours avec deux valeurs (`f(clef, texte)` pour un bouton, `f(clef, valeur)` pour les autres, `f(groupe, clef)` pour un bouton radio), prend la police et la taille du texte du moment, et suit l'agrandissement du canevas ; `valeur_objet(clef)` lit sa valeur, `change_objet(clef, valeur)` la change, `retire_objet(clef)` l'enlève, et `retire_objets()` les enlève tous (pour changer d'écran).
- **Animer et réagir** : `animer(fonction, délai)`, `quand_clic(f)`, `quand_souris(f)`, `quand_glisse(f)` (souris déplacée bouton appuyé, ou doigt sur une tablette), `saisie(clef, x, y, f)` (un champ de saisie posé dans le canevas ; Entrée, ou un clic dans un autre champ, appelle `f(clef, valeur)`, la valeur étant un texte, que `nombre(valeur)` convertit en nombre à virgule, avec une virgule ou un point ; `active_saisie(clef)` donne la main à un champ, `saisie_active()` dit lequel l'a, `largeur_saisie(l)` règle la largeur des champs suivants, qui prennent aussi la police et la taille du texte du moment), `touche_enfoncée(nom)` (Vrai tant que la touche est tenue : la bonne façon de déplacer un objet en douceur, dans la fonction d'`animer`), `quand_relâche(f)` (au relâchement d'une touche), `quand_touche(f)` (la fonction reçoit le nom français de la touche : `"gauche"`, `"droite"`, `"haut"`, `"bas"`, `"espace"`, `"entrée"`, `"échap"`…, ou la lettre, comme `"a"`), `arrête()`.
- **Images et sons** : `img = charge_image(nom)`, `place_image(img, x, y)`, `snd = charge_son(nom)`, `joue_son(snd)`. Un simple nom (`"chat.png"`, `"miaou.wav"`) désigne un fichier des répertoires **images** ou **sons** du projet ; une adresse avec un `/` désigne un fichier du site (`exemples/médias/ding.wav`), et une adresse complète, un autre site (`https://…`). `liste_sons()`, `liste_images()` et `liste_données()` donnent les noms des fichiers du projet ; `liste_sons()` et `liste_images()` y ajoutent les médias du site, dont la liste `docs/exemples/médias/index.json` est écrite par `version.py` (GitHub Pages ne sait pas lister un répertoire). Une application Web emporte tout `exemples/médias/` quand le programme s'en sert (ou appelle `liste_sons()` ou `liste_images()`).
- **Le projet** : `importe "outils"` (ou `importe "jeux/outils"`) rend disponibles les fonctions et les variables d'un autre programme du projet (voir plus bas).
- **Pages Internet** : `ouvre_page("https://…")` ouvre une page dans un nouvel onglet (après un clic ou une touche, comme l'exige le navigateur).
- **Fichiers** : `texte = charge_données(nom)` lit un fichier du répertoire **données** du projet (`charge_données("capitales.csv")`), et `sauve_données(nom, valeur)` en écrit un (ou le remplace), qui part avec le projet. `charge_programme(nom)` lit le code d'un programme du projet, `sauve_programme(nom, code)` l'écrit, et `vérifie_code(code)` dit s'il se compile, sans l'exécuter (`""`, ou le message d'erreur) ; ces trois-là n'existent pas dans une application Web. `lit_fichier(f)` lit un fichier de l'ordinateur, y compris depuis la version en ligne : un navigateur ne peut lire que les fichiers que l'utilisateur choisit lui-même, si bien qu'une fenêtre de sélection s'ouvre, et `f(texte)` reçoit le contenu du fichier choisi (`lit_fichier(f, a)` : `f(texte, a)`) ; le programme, lui, continue sans attendre, comme pour une question. Si l'élève annule, `f` n'est pas appelée. Le contenu reste dans le navigateur, rien n'est envoyé. `écrit_fichier(nom, texte)` enregistre le texte dans le dossier Téléchargements, ce qui fonctionne sur tous les ordinateurs et toutes les tablettes.
- **Les données du projet** : le bouton **▦ Données**, au-dessus de l'éditeur, remplace le programme par des onglets **Don0**, **Don1**, **Don2**… que l'on ajoute avec **＋** et que l'on retire avec **−** (l'onglet **Don0** est toujours là : **−** le vide seulement) ; **↶** annule les retraits, les vidages et les remplacements par un fichier. Le bouton devient alors **✎ Code**, pour revenir au programme. On y tape ou colle des données, ou on y charge un fichier de l'ordinateur (**📂 Charger un fichier…**). À l'exécution, chaque onglet non vide est ajouté au début du programme sous la forme `don0 = """…"""`, ou `'''…'''` si les données contiennent `"""` ; dans les rares cas où aucune des deux ne convient (les données contiennent `"""` et `'''`, finissent par un guillemet, contiennent un accent grave…), sous la forme `don0 = de_base64("…")`, qui transporte n'importe quel texte sans le modifier : le programme s'en sert par la variable `don0`, `don1`… Un onglet vide ne crée pas de variable. Un programme peut aussi écrire dans un onglet avec `range_données("don1", valeur)` (une liste ou un nombre y est écrit comme `affiche` l'écrirait) ; il peut créer l'onglet qui vient juste après le dernier (`don3` après `don0` à `don2`), mais pas plus loin. `prend_données("don1")` renvoie le texte actuel d'un onglet, y compris ce qu'un `range_données` vient d'y écrire. Les onglets appartiennent au **projet**, pas à un programme : tous les programmes du projet, et ceux qu'ils importent, voient les mêmes `don0`, `don1`… Ils sont enregistrés dans le navigateur avec le projet, et rangés dans le projet exporté (`onglets/don0.txt`, `onglets/don1.txt`…).
- **Pour aller plus loin** : environ 180 instructions supplémentaires portant des noms français (`mélange`, `pgcd`, `commence_par`, `loi_normale`…), décrites dans le glossaire du mode d'emploi.

Vingt exemples, du premier « Bonjour » jusqu'à un piano de trois octaves, quatre jeux (un casse-briques, le serpent, les envahisseurs de l'espace et astéroïdes, qui gardent chacun leur meilleur score dans l'onglet don0 de leur projet (retrouvé à chaque fois qu'on rouvre l'exemple) : un dictionnaire JSON `{"Astéroïdes": 1250, "Serpent": 18}`, auquel ils ne touchent pas si don0 contient autre chose), un mini tableur et un atelier de formes qui réunit tous les objets du canevas, en passant par la tortue, une balle qui rebondit, une courbe mathématique et un petit logiciel de dessin, se trouvent dans le répertoire **Exemples**. Chaque exemple est un **projet** : un clic l'ouvre dans un projet à son nom (« 15. Casse-briques » devient le projet et le programme « Casse-briques »), à la place du projet en cours, qui rejoint **Mes projets**. Un exemple est un projet de passage : il n'entre pas dans **Mes projets** tant qu'il garde son nom. Pour garder ses changements, l'élève renomme le projet (✏️ Renommer), qui devient alors un projet comme les autres ; s'il quitte un exemple qu'il a modifié sans l'avoir renommé, la Pythonerie lui propose de lui donner un nom (sinon, ses changements sont effacés), et un exemple qu'il n'a pas modifié est simplement refermé. Un nouveau clic sur un exemple repart donc toujours de l'original. Les onglets de données d'un exemple (le meilleur score d'un jeu, dans don0) sont gardés à part, pour chaque exemple et chaque élève : on les retrouve en rouvrant l'exemple. Les images et les sons des exemples restent dans `docs/exemples/médias/`, que les programmes désignent par leur chemin (`exemples/médias/ding.wav`) : ils ne sont pas copiés dans le projet. Les exemples restent écrits dans `docs/exemples/*.pyf`, listés dans `docs/exemples/index.json` (le champ facultatif `"programme"` y nomme le programme quand le titre contient un signe refusé dans un nom de programme, comme l'apostrophe de « L'atelier de formes ») ; un exemple qui aurait besoin de plusieurs programmes ou de données peut y être déposé en projet (`.zip` ou `.json`, comme dans les Matériels).

## Le projet de l'élève

Les programmes de l'élève forment un **projet**. Ce peut être une collection de programmes indépendants, ou un ensemble de programmes qui se servent les uns des autres.

- **Le nom du projet** est affiché en haut de la liste des programmes : « Sans Nom » au départ, en gris. Un clic dessus ouvre la liste **Mes projets** : tous les projets de l'utilisateur gardés dans ce navigateur (au-delà de dix, les dix derniers ouverts, le projet ouvert en tête, puis une ligne « ▸ Les N autres projets » qui déroule les autres par ordre alphabétique, dans une zone qui défile), pour en ouvrir un, en supprimer un (🗑), en créer un nouveau, renommer, exporter ou fermer le projet ouvert (aussi dans le menu ☰, avec **🗑️ Supprimer le projet…**). **✖ Fermer le projet** le range dans la liste, comme quand on change de projet (avec la même question pour un projet sans nom ou un exemple modifié), puis vide l'espace de travail ; **↶ Revenir au projet précédent** le rouvre.
- **Mes projets** : les projets sont gardés dans **IndexedDB**, un par nom, sous le nom de l'utilisateur : « Unique » en mode Utilisateur unique, sinon le nom tapé par l'élève, qui retrouve ainsi ses projets à chaque connexion. Quand on change de projet (un autre de la liste, **Nouveau projet**, **Charger un projet**, un projet des Matériels) ou qu'on se déconnecte, le projet ouvert est rangé dans la liste sous son nom, à la place de sa version précédente : il n'y a jamais deux projets du même nom. La Pythonerie ne demande rien, sauf si le projet ouvert n'a pas encore de nom, ou si c'est un exemple que l'élève a modifié sans le renommer : elle propose alors de lui donner un nom, ou de ne pas le garder. Un exemple qu'il n'a pas modifié est refermé sans rien dire, et n'entre pas dans la liste (voir plus haut). **↶ Revenir au projet précédent** (menu ☰) rouvre le projet que l'on vient de quitter. Si un projet chargé porte le nom d'un projet de la liste, on choisit d'ouvrir celui de la liste, de charger le nouveau sous un autre nom (« Mon jeu 2 ») ou de remplacer celui de la liste ; pour un projet des Matériels déjà chargé, c'est le moyen de le retrouver avec ses modifications.

- **Les programmes** se rangent dans des répertoires et se déplacent en les faisant glisser. Au survol d'un programme, on peut le renommer, l'exporter dans un fichier `.pyf` (pour « Python francisé » : l'extension évite de confondre un programme de la Pythonerie avec un programme Python) ou le supprimer. Pour en supprimer plusieurs à la fois, on les choisit avec Cmd+clic ou Ctrl+clic (un par un) ou Maj+clic (une suite), puis on clique sur **Supprimer** dans le bandeau, ou on appuie sur la touche Suppr. Le menu ☰ permet aussi de copier un programme ou d'importer des fichiers (un programme `.pyf`, ou `.py` s'il a été écrit ailleurs).
- **Archiver tous ses projets** : **🗄️ Archiver tous mes projets** (menu ☰) range tous les projets de l'utilisateur dans un seul fichier, `Mes_projets_aaaa_mm_jj_hh_MM.zip` (avec le nom de l'élève en mode plusieurs élèves). Il contient `archive.json` (la liste des projets, avec leur date de modification) et un fichier `projets/<nom>.zip` par projet, exactement celui que donnerait **Exporter le projet** : on peut donc aussi en sortir un seul. **🗄️ Charger une archive…** (ou **Charger un projet**, ou un glisser-déposer : l'archive est reconnue) fusionne ses projets avec ceux de la liste : un projet nouveau est ajouté ; pour un nom déjà pris, la Pythonerie montre les deux dates de modification et demande lequel garder : le sien, celui de l'archive, ou les deux (celui de l'archive devient « Jardin 2 »), avec une case pour faire de même pour les doublons suivants. C'est la façon de passer tous ses projets d'un ordinateur à un autre, ou d'en garder une sauvegarde.
- **Copier-coller entre projets** : l'icône ⧉ d'un programme ou d'un fichier des répertoires images, sons et données le met de côté (sur un programme choisi parmi plusieurs, ou avec Cmd/Ctrl+C, toute la sélection). Un bandeau « 📋 … Coller » apparaît alors au-dessus de la liste, et y reste quand on change de projet : **Coller** (ou Cmd/Ctrl+V) recopie le tout dans le projet ouvert, les programmes dans le répertoire courant, les fichiers dans leur répertoire ; un nom déjà pris devient « nom 2 ». Ce qui est copié est oublié à la déconnexion.
- **`importe "outils"`**, sur une ligne à part, rend disponibles dans un programme les fonctions et les variables du programme « outils » du projet. Le chemin peut désigner un sous-répertoire : `importe "jeux/outils"`. Le programme est cherché à partir du répertoire du programme qui importe, puis à la racine du projet. Un programme importé plusieurs fois ne l'est qu'une fois, des programmes qui s'importent en boucle donnent une erreur, et une erreur dans un programme importé est signalée avec son nom (« ligne 2 de « outils » »).
- **Trois répertoires fixes**, en haut de l'arbre, reçoivent les fichiers du projet : **images** (png, jpg, gif, svg, webp), **sons** (wav, mp3, ogg) et **données** (txt, csv, tsv, json, md). On y fait glisser des fichiers depuis l'ordinateur, ou on utilise le bouton **＋** du répertoire ; un fichier glissé ailleurs dans l'arbre va dans le répertoire qui lui correspond. Un clic sur un fichier montre l'image, joue le son ou affiche le début des données. Dans le code, on désigne un fichier par son seul nom : `charge_image("chat.png")`, `charge_son("miaou.wav")`, `charge_données("notes.csv")`. Un fichier fait au plus 5 Mo.
- **Où tout est rangé** : les programmes dans le `localStorage` du navigateur, les fichiers du projet dans **IndexedDB**, une autre réserve du navigateur, qui accepte des fichiers bien plus gros. Rien ne quitte l'ordinateur, que la Pythonerie soit ouverte en ligne ou depuis `serveur.py`.
- **Exporter le projet** (menu ☰) crée un fichier `nom_du_projet_aaaa_mm_jj_hh_MM.zip` en mode Utilisateur unique, `nom_du_projet_élève_aaaa_mm_jj_hh_MM.zip` en mode plusieurs élèves (les espaces deviennent des `_`) ; un projet « Sans Nom » reçoit d'abord un nom, que l'on demande à l'élève. Le fichier, enregistré dans le dossier Téléchargements, contient tout le projet, sous forme de fichiers ordinaires que l'on peut ouvrir en décompressant l'archive :

  ```text
  projet.json                 {"format": "projet-pythonerie", "version": 3, "nom": "Mon jardin", "élève": "Léa", "créé": "…"}
  programmes/Quiz.pyf         les programmes, dans leurs répertoires
  programmes/jeux/outils.pyf
  onglets/don0.txt            les onglets de données (bouton ▦ Données)
  images/  sons/  données/    les fichiers du projet
  ```

  Les images et les sons gardent leur format : un projet zippé est bien plus léger qu'un fichier texte qui les recoderait.
- **Créer une application Web** (menu ☰, ou sous le nom du projet) fait d'un programme du projet un petit site qui tourne sans la Pythonerie. S'il y a plusieurs programmes, l'élève choisit le programme principal. Celui-ci est assemblé comme pour ▶ Exécuter (programmes importés, onglets de données), puis traduit en LispE dès l'export : une erreur dans le programme est montrée dans la console, et l'application n'est pas créée. Le fichier `nom_du_projet_application_web.zip` contient un dossier :

  ```text
  index.html, appli.js, appli.css   la page : le canevas, ▶ Lancer, ↻ Recommencer, ■ Arrêter, ⛶ Plein écran,
                                    et la console, qui n'apparaît que si le programme y écrit
  programme.js                      le programme traduit en LispE, bibliothèque.lisp et les données du projet
  js/canevas.js, js/erreurs.js      les mêmes fichiers que dans la Pythonerie
  lispe/                            LispE en WebAssembly
  polices/                          Inter et JetBrains Mono
  images/  sons/  données/          les fichiers du projet
  exemples/médias/                  les médias du site, si le programme s'en sert
  vendor/three/                     three.js, si le programme montre une scène 3D (montre_3d)
  LISEZMOI.txt                      comment l'ouvrir
  ```

  `appli.js` (modèle : `docs/appli/`) tient le rôle de `pythonerie.js` : les questions de `demande()` et de `lire()` et le choix de fichier de `lit_fichier()` (avec leurs fonctions de rappel), `écrit_fichier()`, `charge_données()`, `prend_données()` et `range_données()` (les onglets vivent le temps de la visite), les animations et les événements. Le bouton ▶ Lancer, sur le canevas, sert de premier clic : le navigateur autorise alors le son, et le clavier va au programme. Comme pour la Pythonerie, le WebAssembly ne se charge que depuis un serveur Web : un double-clic sur `index.html` ne suffit pas ; on met le dossier sur un site (GitHub Pages, le site de l'école), ou l'on lance `python3 -m http.server` dans le dossier.
- **Un projet en JSON** : un projet peut aussi être écrit d'un seul bloc de texte, en JSON. C'est la forme que Claude (ou une autre IA) sait produire dans une conversation : l'élève le colle avec **📋 Coller un projet (JSON)…** (menu ☰), ou le charge depuis un fichier `.json` ; un enseignant peut le déposer dans Matériels. Les programmes, les onglets, les données et les images SVG y sont écrits en texte ; une autre image ou un son est donné en base64, ou par une adresse `https://` que la Pythonerie télécharge au chargement, si le site le permet. Le format est décrit dans [POUR_CLAUDE.md](POUR_CLAUDE.md). L'export, lui, se fait toujours en `.zip`. Avec `serveur.py`, une copie est aussi conservée sur le serveur, pour l'enseignant (voir plus bas).
- **Charger un projet** remplace tout le projet en cours par celui du fichier `.zip` ou `.json` (on peut aussi le faire glisser dans la liste des programmes). Une archive dont tout le contenu est dans un dossier (un dossier compressé par le Finder ou l'Explorateur) est acceptée ; les fichiers qui ne vont dans aucun répertoire du projet sont laissés de côté, et la console les nomme. Le projet en cours rejoint la liste **Mes projets** (voir plus haut).
- Par défaut, la Pythonerie est en mode **Utilisateur unique** : pas de connexion, l'utilisateur s'appelle « Unique » et le bouton **👤** est désactivé. Ce mode convient à un ordinateur personnel. Sur un ordinateur partagé, on décoche **Utilisateur unique** dans le menu ☰ : la Pythonerie passe en mode **plusieurs élèves**, et chacun doit taper son nom. Ce choix est gardé dans le navigateur. Un établissement peut aussi imposer le mode plusieurs élèves à tout le monde, dans le fichier `config.json` (voir plus bas).
- En mode plusieurs élèves, le bouton **👤** en haut de l'écran affiche le nom de l'élève (« inconnu » au départ). Il faut le taper pour exécuter du code. Il est oublié quand on ferme l'onglet, ce qui convient aux ordinateurs partagés. Un deuxième clic sur **👤** déconnecte l'élève : son projet ouvert rejoint sa liste **Mes projets** (s'il n'a pas de nom, la Pythonerie lui en demande un), puis l'espace de travail est vidé (programmes, répertoires, onglets de données, fichiers du projet, historique de la console) et la liste se ferme, jusqu'à la prochaine connexion : un autre élève ne voit que ses propres projets. Si un élève part sans se déconnecter, le projet qu'il a laissé est rangé dans sa liste dès que quelqu'un d'autre se connecte. Les projets restent dans le navigateur de l'ordinateur : pour les emporter ailleurs, ou pour plus de discrétion sur un ordinateur partagé, on les exporte.

## Pour les enseignants : le répertoire Matériels

Le répertoire `docs/matériels/` reçoit le matériel de cours destiné aux élèves. Il apparaît dans la colonne de gauche, sous la forme d'une liste déroulante **Matériels**, au-dessus des **Exemples**, dès qu'il contient au moins un fichier décrit dans son `index.json`.

- **Des projets** (`.zip`, ou `.json` pour un projet écrit en JSON, par exemple par Claude) : un projet exporté depuis la Pythonerie (menu ☰, **Exporter le projet**), avec ses programmes, ses onglets de données et les fichiers de ses répertoires images, sons et données. On peut aussi en préparer un à la main : un dossier qui contient `projet.json` (`{"format": "projet-pythonerie", "version": 3, "nom": "Mon projet"}`), `programmes/*.pyf` et au besoin `onglets/`, `images/`, `sons/`, `données/`, que l'on compresse en `.zip`. Un clic de l'élève le charge dans son espace, avec son nom (que l'élève peut changer), à la place de son projet en cours (qui rejoint sa liste **Mes projets**) ; s'il l'a déjà chargé, il retrouve sa version, avec ses modifications : c'est la façon de lui donner un point de départ complet, plutôt que des fichiers épars. Le répertoire contient, entre autres, `quiz_des_capitales.zip`, deux programmes (« Quiz » importe « outils »), un fichier de données et deux sons ; et `zaxxon.zip`, le jeu d'arcade en perspective isométrique, en trois programmes (« Zaxxon » importe `outils/projection`, la perspective et les boîtes en relief, et `outils/forteresse`, la lecture du plan), le plan de la forteresse dans `données/forteresse.txt` (une ligne par rangée : `C` canon, `E` réservoir, `R` radar, `mur 2 1` pour un mur et sa fenêtre), que l'élève peut modifier pour inventer sa forteresse, et ses sons dans `sons/` ; et `cartes.zip`, une pile de cartes à la HyperCard : l'**Éditeur** dessine des cartes (textes sur plusieurs lignes, rectangles, disques, images, boutons qui mènent à la carte suivante, précédente, première, dernière, à une carte par son nom ou à une autre pile — « pile : apprendre.json » : les piles s'enchaînent ; un son joué au clic d'un bouton ou à l'ouverture d'une carte, pris dans `liste_sons()` ; on pose un élément d'un clic, on le choisit, le fait glisser et change ses réglages) et les range en JSON dans le répertoire `données` avec `sauve_données` (une pile par fichier : `pile.json`, `apprendre.json`… ; « ＋ Nouvelle pile » en commence une) ; le **Lecteur** les montre, avec de vrais boutons et les flèches du clavier, et sa liste déroulante choisit parmi toutes les piles du projet. Trois piles sont fournies : « Apprendre à programmer avec la Pythonerie », un petit cours en dix cartes (afficher, variables, conditions, boucles, fonctions, listes, dessin, animation), une visite du système solaire, et « Les déclinaisons latines » (`latin.json`, neuf cartes : les six cas, puis rosa, lupus, le neutre templum, canis, portus et diēs, chacune avec son tableau, un exemple, sa traduction et une image prise sur Wikimedia Commons — images libres, auteurs et licences sur la dernière carte, Crédits) ; l'Éditeur et le Lecteur importent `outils/cartes`, qui décrit le format et dessine une carte de la même façon. Une carte ou un bouton peut aussi avoir un **script** : une fonction du programme `biblios.pyf`, que l'on écrit soi-même, puis que l'on ajoute avec un numéro dans le `selon` de sa fonction `extensions(id)` (`cas 1:` → `bravo()`…). L'Éditeur relit ce `selon` et propose la liste « 1 : bravo() », « 2 : voyage_vers_mars() »… ; il vérifie au démarrage que `biblios` se compile toujours (`vérifie_code`), mais ne le modifie jamais. La carte ou le bouton garde le numéro choisi ; le Lecteur importe `biblios` et appelle `extensions(numéro)` à l'ouverture de la carte ou au clic du bouton (action « aucune » pour un bouton qui n'a qu'un script), après avoir montré la console. Dans la pile du cours, chaque exemple a un bouton « ▶ Exécute » relié à sa fonction (`exemple_afficher`, `exemple_boucles`…). Le Lecteur, exporté par « Créer une application Web », devient un petit site. On y trouve aussi `systeme_solaire_3d.zip`, l'exemple de la 3D : les huit planètes et la Lune, avec leurs textures (Solar System Scope, CC BY 4.0), sur leurs orbites ; `asteroides_3d.zip`, le jeu d'Astéroïdes de l'exemple 19 en relief (des rochers habillés de la vraie surface de l'astéroïde Bennu, photographiée par la sonde OSIRIS-REx de la NASA, domaine public, et de celle de la Lune ; la même logique en points, montrée sur un plan 3D vu d'en haut ; tous les objets créés au départ dans des réserves, puis cachés et réutilisés : une scène 3D garde ses objets, il ne faut pas en créer à chaque image) ; et `ma_classe.zip`, pour le mode classe (voir plus bas).
- **Des programmes** (`.pyf`) : un clic de l'élève en crée une copie dans son projet en cours, qu'il peut modifier, ou ouvre sa copie s'il l'a déjà.

Après avoir ajouté, remplacé ou retiré des fichiers, l'enseignant lance le script `inventaire.py`, placé dans le répertoire :

```bash
cd docs/matériels
python3 inventaire.py            # demande un titre et une explication pour chaque nouveau fichier
python3 inventaire.py --revoir   # permet aussi de changer les explications existantes
```

Le script parcourt le répertoire et ses sous-répertoires, demande une explication pour chaque projet ou programme qu'il ne connaît pas encore, retire de la liste les fichiers qui ont disparu, et écrit `index.json`. Les autres fichiers sont ignorés : des données, des images ou des sons se placent dans un projet. Le matériel est servi par le site lui-même, en ligne comme avec `serveur.py`.

## Utiliser la Pythonerie sur sa machine

Pour travailler sans connexion, ou pour une salle de classe, on peut lancer la Pythonerie sur son ordinateur. Il suffit de Python 3, sans aucune autre installation :

```bash
git clone https://github.com/clauderouxster/Pythonerie.git
cd Pythonerie
python3 serveur.py          # élèves : http://localhost:8000 ; mode administrateur : http://localhost:8001
```

Le serveur ouvre **deux ports** : celui des **élèves** (8000) et celui du **mode administrateur** (8001), qui n'écoute par défaut que sur la machine du serveur. Il fait trois choses :

- il **fournit les fichiers** de la Pythonerie aux navigateurs, sur les deux ports ;
- il **garde une copie des projets** : chaque fois qu'un élève exporte son projet, celui-ci est téléchargé sur son poste, comme d'habitude, et une copie est enregistrée dans le répertoire `projets/` du serveur. L'enseignant dispose ainsi des projets de tous ses élèves en un même lieu ;
- il **reçoit les données que les programmes des élèves envoient à un professeur**, pour un examen, un sondage ou une expérience, et les donne aux programmes du professeur, en mode administrateur (voir ci-dessous).

Les projets en cours, eux, restent dans le navigateur de chaque élève, et le serveur n'exécute **aucun** programme : la traduction et l'exécution se passent toujours dans le navigateur, exactement comme avec la version en ligne.

Les projets du serveur ne peuvent être ni remplacés ni supprimés depuis la Pythonerie : deux projets du même nom sont gardés tous les deux (`Mon_jardin_Léa_2026_10_08_14_30.zip`, puis `Mon_jardin_Léa_2026_10_08_14_30_2.zip`), et la liste des projets n'est jamais montrée aux élèves. Un projet peut peser jusqu'à 100 Mo. Seul l'enseignant décide de ce qu'il en fait, directement dans le répertoire.

### Le mode administrateur : les données des examens

Sur le port administrateur (`http://localhost:8001`), la Pythonerie affiche un bouton **🔑 Mode administrateur** dans son en-tête. La première fois, le professeur y **crée son compte** (un identifiant et un mot de passe de 6 caractères au moins) ; ensuite, il s'y **connecte**. Le mot de passe n'est jamais enregistré : `serveur/comptes.json` ne garde que son empreinte (scrypt, avec un sel propre à chaque compte), et la connexion dure 12 heures, le temps de l'onglet. **Se déconnecter** (un nouveau clic sur 🔑) arrête le programme en cours et ferme le projet ouvert, qui rejoint **Mes projets** : la personne suivante ne voit ni les programmes du professeur, ni ses données. À la création du compte, le serveur crée le répertoire du professeur, `serveur/professeurs/<identifiant>/`. Le port des élèves ne montre jamais ce bouton, et refuse toutes les opérations du mode administrateur. Comme les deux ports sont deux « origines » différentes pour le navigateur, les projets du professeur sur le port administrateur ne se mélangent pas avec ceux d'un élève qui utiliserait la même machine.

- **Les élèves écrivent**, sans pouvoir relire : `sauve_dans_serveur("dupont", "contrôle1/réponses.json", valeur)` écrit le fichier dans le répertoire du professeur `dupont` (l'identifiant peut être demandé au début de l'examen, avec `demande`). Le chemin est gardé tel quel, avec ses sous-répertoires : au professeur de faire mettre le nom de l'élève dans le chemin s'il veut un fichier par élève. `login()` donne ce nom, celui sous lequel l'élève travaille dans la Pythonerie (« Unique » en mode utilisateur unique, son identifiant vérifié en mode classe, `""` dans une application Web) : `sauve_dans_serveur("dupont", f"contrôle1/{login()}.json", réponses)`. Une valeur qui n'est pas un texte est écrite en JSON ; `sauve_dans_serveur(professeur, chemin, valeur, f)` appelle `f(Vrai)` une fois le fichier enregistré. Les extensions acceptées sont `.txt`, `.json`, `.csv`, `.tsv` et `.md` (sans extension : `.txt`), 5 Mo au plus par fichier ; un chemin avec `..` est refusé. Les envois d'une même page partent l'un après l'autre, dans l'ordre du programme.
- **Rien ne se perd** : si un fichier est réécrit, la version précédente est gardée à côté, sous son nom suivi de sa date (`réponses_2026-10-13_10-42-05.json`).
- **L'index** : à chaque écriture, le serveur met à jour `serveur/professeurs/<identifiant>/index.json`, une entrée par version : `{"chemin", "élève", "date", "taille", "actuel"}` (`élève` : le nom sous lequel l'élève travaille dans la Pythonerie).
- **Le professeur lit**, avec des programmes qu'il écrit dans la Pythonerie du port administrateur, une fois connecté : `liste_dans_serveur("contrôle1", f)` appelle `f(entrées)` avec les entrées de l'index sous `contrôle1/` (`""` : toutes), et `lit_dans_serveur("contrôle1/réponses.json", f)` appelle `f(contenu)` avec le texte du fichier, ou sa valeur pour un `.json`. Un professeur ne lit que son propre répertoire. Comme `demande`, ces fonctions rendent la main tout de suite, et acceptent un argument de plus, rendu à `f`.
- Le serveur n'exécute toujours aucun programme : la correction ou les statistiques tournent dans le navigateur du professeur.

### Le mode classe : des élèves identifiés

Pour un examen, le professeur peut réserver le serveur à ses élèves, identifiés par l'**identifiant unique** que l'école leur a donné.

1. **La liste des élèves.** En mode administrateur, une fois connecté, le professeur ouvre **« Ma classe (pour le professeur) »** dans les Matériels et l'exécute. Il colle sa liste d'un coup dans la zone de gauche, une ligne par élève, avec l'identifiant et le nom séparés par une tabulation (une copie depuis un tableur) ou par un point-virgule. La colonne qui contient des chiffres est prise pour l'identifiant. **« Ajouter au tableau ▶ »** ajoute ces élèves à ceux du tableau Identifiant | Nom (14 lignes par page, ◀ ▶) : un élève déjà présent (même identifiant, sans compter les majuscules ; ou, sans identifiant, même nom) n'est pas ajouté une deuxième fois, et le message dit lesquels étaient déjà là. On peut ainsi compléter une liste en plusieurs fois. **Vider le tableau** repart de zéro. Il corrige ou complète les cases, puis **Enregistrer**, qui refuse deux élèves avec le même identifiant, range la liste dans `serveur/professeurs/<identifiant>/élèves.json` : `[{"identifiant": "id100", "nom": "Jean Lupin"}, …]`. Le programme relit la liste enregistrée à son démarrage (et avec **Recharger**). Il se sert de `sauve_élèves(liste, f)`, réservé au mode administrateur : le serveur refuse une liste où il manque un identifiant, ou dont deux identifiants sont pareils (sans compter les majuscules). `index.json` et `élèves.json`, à la racine du répertoire, ne s'écrivent jamais avec `sauve_dans_serveur`.
2. **Le lancement.** `python3 serveur.py --professeur dupont` demande le mot de passe de `dupont` dans le terminal, sans l'afficher. Il n'est jamais écrit sur la ligne de commande, où il resterait dans l'historique. Le serveur vérifie le compte et la liste, puis passe en mode classe.
3. **La connexion des élèves.** Sur le port des élèves, le mode plusieurs élèves est imposé. Le bouton **👤** demande l'**identifiant**, et le serveur vérifie qu'il est dans la liste, sans compter les majuscules ni les espaces. Un identifiant inconnu est refusé. L'élève reste connecté le temps de l'onglet (12 heures au plus), même s'il recharge la page.
4. **Pendant l'examen.** `login()` donne l'identifiant de l'élève. `sauve_dans_serveur` n'écrit que chez le professeur de la classe. Chaque envoi porte l'identité vérifiée par le serveur, `"élève"` (l'identifiant) et `"nom"` dans l'index, et non ce que dirait le navigateur. Le professeur, connecté au mode administrateur, peut aussi écrire, sous le nom « (le professeur) ».

L'identifiant tient lieu de preuve : il doit rester connu du seul élève, comme un mot de passe. Techniquement, le jeton de l'élève voyage dans l'en-tête HTTP `X-Pythonerie-Eleve`, sans accent, car les noms d'en-têtes n'acceptent que l'ASCII.

Le répertoire `serveur/` (comptes et données des professeurs) n'est jamais publié avec le dépôt (`.gitignore`).

Options :
- `--port 8080` pour choisir le port des élèves, `--port-admin 8081` celui du mode administrateur ;
- `--hôte 0.0.0.0` pour que les élèves d'une salle de classe se connectent depuis leur poste ;
- `--hôte-admin 0.0.0.0` pour ouvrir aussi le mode administrateur au réseau (depuis une tablette, par exemple) : il reste protégé par les comptes, mais par défaut il n'écoute que sur la machine du serveur ;
- `--projets /un/répertoire` pour ranger les projets ailleurs que dans `projets/`, `--données /un/répertoire` pour les comptes et les données des professeurs (par défaut `serveur/`) ;
- `--professeur dupont` pour le mode classe (le mot de passe est demandé au lancement) ;
- `--sans-navigateur` pour ne pas ouvrir de navigateur au lancement.

Le fichier `docs/config.json` contient les réglages de l'installation :

```json
{
    "multi_utilisateur": false
}
```

Avec `"multi_utilisateur": true`, la Pythonerie démarre en mode plusieurs élèves pour tout le monde : chaque élève doit taper son nom, et la case **Utilisateur unique** du menu ☰ est désactivée, si bien qu'on ne peut pas revenir au mode Utilisateur unique. De plus, chaque nouvelle session (nouvel onglet, navigateur relancé) commence avec un espace vide, même si l'élève précédent est parti sans se déconnecter ; un simple rechargement de la page garde le travail en cours. Les élèves doivent donc exporter leur projet avant de partir.

## Comment ça marche

Le programme de l'élève est traduit en **LispE**, le langage qui est réellement exécuté, directement dans le navigateur. Rien n'est envoyé à un serveur pour être exécuté, y compris quand on utilise `serveur.py`, qui ne reçoit que les copies des projets exportés. Le bouton **λ LispE**, au-dessus de l'éditeur, montre le code LispE produit, pour les curieux.

## Protection des données (RGPD)

La Pythonerie est parfaitement compatible avec le **RGPD** européen et avec ses équivalents canadiens, la **LPRPDE** (loi fédérale) et la **Loi 25** du Québec, pour une raison simple : tout s'exécute dans le navigateur. Une fois la page chargée, rien ne transite par le réseau.

- **Aucune donnée n'est envoyée** : les programmes, les images, les sons et les données du projet, le nom de l'élève et l'historique de la console restent dans le navigateur de l'ordinateur. Aucun serveur ne les reçoit, aucun compte n'est créé.
- **Aucun pistage** : ni cookie, ni mesure d'audience, ni publicité, ni service tiers. L'éditeur et les polices de caractères sont fournis par le site lui-même, sans appel à un autre site (pas de Google Fonts, pas de CDN).
- **Le nom de l'élève** n'est qu'une étiquette : il sert à nommer les projets exportés. Il est oublié à la fermeture de l'onglet, et la déconnexion efface tout l'espace de l'élève. Chaque établissement peut d'ailleurs donner à ses élèves un identifiant propre, plutôt que leur vrai nom : c'est plus discret, et cela évite de confondre deux élèves qui portent le même nom.
- **Les projets exportés** sont des fichiers enregistrés sur l'ordinateur, dans le dossier Téléchargements. En ligne, ils ne sont envoyés nulle part : c'est l'élève ou l'enseignant qui décide de les transmettre.
- **Les données envoyées à un professeur** (`sauve_dans_serveur`) n'existent qu'avec `serveur.py`, sur la machine de l'établissement : elles y sont rangées avec le nom sous lequel l'élève travaille et l'heure, dans `serveur/professeurs/`. L'établissement décide combien de temps il les garde ; la version en ligne n'a pas de serveur, et ces fonctions y donnent une erreur.
- **Les photos** : une photo d'un élève, placée dans le répertoire images d'un projet, est une donnée personnelle. Elle reste dans le navigateur comme le reste du projet, mais elle part avec le projet quand on l'exporte : à garder en tête avant de partager un projet.

Deux remarques pour les établissements :

- Comme pour toute page web, l'hébergeur du site (GitHub Pages) voit passer l'adresse de l'ordinateur au moment où la page est téléchargée. Pour l'éviter, on peut lancer la Pythonerie sur une machine de l'établissement (voir [Utiliser la Pythonerie sur sa machine](#utiliser-la-pythonerie-sur-sa-machine)) : la seule donnée qui passe alors par le réseau, celui de l'établissement, est la copie des projets exportés que reçoit cette machine, pour l'enseignant.
- Un programme qui charge une image, un son ou un fichier depuis une adresse `https://…` d'un autre site contacte ce site. Les exemples fournis n'utilisent que des fichiers de la Pythonerie.

## Limites connues

- Le programme s'exécute dans la page : pendant qu'il tourne, la page ne réagit plus. Une boucle `tantque` sans fin (`tantque Vrai:` sans `sortir`) est arrêtée au bout de 10 millions de tours (moins d'une seconde), avec un message qui l'explique ; une boucle `tantque` légitime ne dépasse pas cette limite. Pour une animation, il faut utiliser `animer`, qui rend la main à la page entre deux images.
- Une erreur d'exécution montre l'expression LispE en cause (« dans le code LispE : (at l 5) »), puis la fonction du programme où elle s'est produite, avec la ligne où cette fonction est définie et ses appelants (« dans la fonction cherche (définie ligne 2 ; ligne 3 du code LispE) — appelée par calcule, elle-même appelée par le programme principal ») ; un clic sur le message mène à la fonction, et ↩ Retour ramène où l'on était. La Pythonerie le déduit de la pile d'appels de LispE, dont chaque étape donne sa ligne dans le code LispE (celle du panneau λ LispE). Elle ne donne pas encore la ligne exacte de l'instruction dans le programme de l'élève ; les erreurs de syntaxe, elles, citent la ligne.
- Un `cas` n'accepte pas un nombre négatif (`cas -1:`).
- `Rien` s'affiche `[]`.
- Pour échanger deux valeurs, on écrit `a, b = b, a`, et non `[a, b] = [b, a]`.
